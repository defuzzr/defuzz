# Unattended Exposure (`report.unattended_exposure`)

`audit.unattended_exposure` (`audit_unattended_exposure(profile_path, *, managed_dir=None, now_fn=time.monotonic, max_entries=None, max_file_bytes=None, max_total_bytes=None, max_seconds=None)`) reads static configuration, plugin manifests, hook registrations and cron job records to report what a Hermes agent is configured to run or change without a person approving each action. It reads settings; it never shows that an agent did anything.

It returns exactly `{'unattended_exposure': <section>, 'findings': [...], 'run_metrics': {'elapsed_ms': <int>}, 'status': 'pass', 'coverage': 'verified' | 'could_not_verify'}`. The caller passes only `profile_path` (the profile directory); every config-derived value is read by the module from `<profile_path>/config.yaml`. `run_metrics` depends on wall-clock time and is kept outside the section, so two runs on an unchanged home give the same raw section and findings. The wiring sheet with every key, label, rule and free string is `audit/wiring/unattended_exposure.json`.

Skill and memory write-approval gates (`skills.write_approval`, `memory.write_approval`) are reported by `audit.write_settings`; this module reuses its config loader and provenance model without duplicating those findings.

## 1. Settings table (`settings`)

`<profile_path>/config.yaml` (at most `MAX_CONFIG_BYTES = 1 MiB`) is parsed with the safe PyYAML loader from the declared `>=6.0.3,<7` dependency range; duplicate mapping keys make the whole file `could_not_verify`. Each row is `{value, source, widens_unattended_action}` with `source` in `config` / `default` / `could_not_verify`. Values are enumerated labels, booleans or counts; config strings are never echoed. The config word `off` is emitted as `approval_off` (`approvals.mode`) or `backup_off` (`updates.pre_update_backup`), because the plain word is sealed as a value in the report. Coercion mirrors the Hermes reader named in the table. `${...}` templates (expanded by Hermes after load, `hermes_cli/config.py:1469-1476`), unknown enum strings (reported as `'other'`) and strings that Hermes would hand to `bool()` are `could_not_verify`.

## 2. Platform toolsets (`platform_toolsets`, `a2a`, `mcp_servers`)

For each `platform_toolsets.<platform>` list (`hermes_cli/tools_config.py:571-646`) the audit resolves, statically, which capability labels it grants: configurable keys count directly; static composites (`hermes-cli`, the `hermes-<messaging>` bundles, `hermes-api-server`, `hermes-acp`, `coding`, `debugging`, `hermes-webhook`, `safe`; `toolsets.py:11-36,166-241`) contribute their configurable subset; `all`/`*` count only when the list names no configurable key (`_composite_toolsets` branch). Plugin toolsets, MCP server names and plugin-platform bundles (`hermes-a2a`, `hermes-teams`, ...) have no static tools and add nothing. `agent.disabled_toolsets` subtracts direct keys and `debugging`; a disabled `hermes-*` bundle removes only non-core tools (`model_tools.py:300-328`).

Each platform row: `powerful_tools`, `high_risk_tools` (terminal, code_execution, cronjob, computer_use), `beyond_default_high_risk_tools` (high-risk labels the platform's shipped default does not already grant; built-in defaults from `hermes_cli/platforms.py:15-35`; plugin platforms default to a bundle with no static tools), `remote` (false for cli/tui/desktop/acp/subagent/cron), `toolset_count`, `peer_or_user_count` (A2A peers + served agents for `a2a`; allow-list entries otherwise; not a count of people). Platforms outside the known Hermes platform list are not keyed by name: their rows (same fields) are in the list `other_platforms`, in sorted-name order. A platform listed here may not be connected: connection depends on credentials the audit does not read. MCP: `configured_count`, `enabled_count`, `disabled_count` only; server names are never emitted.

## 3. Plugins and hooks (`plugins`, `hooks`)

`plugins/<name>/plugin.yaml|plugin.yml` and `plugins/.install-metadata.json` (at most 256 KiB each) are read without importing plugin code. One level of category directories is followed (`hermes_cli/plugins_discovery.py:141-186`). Gate names follow `hermes_cli/plugins_manifest.py:564-565`: top-level key = manifest `name` (default: directory name), category key = `<category>/<dir>`. A plugin is `enabled` when `plugins.enabled` is a list naming it, `plugins.disabled` does not, and its kind is not `exclusive`/`model-provider` (`plugins_discovery.py:269-345`). When the manifest declares no `kind` and the plugin is a warning candidate, the first 8192 bytes of its `__init__.py` are scanned for the same kind markers Hermes uses (`plugins_manifest.py:287-298,539-546`); only the resulting label is kept. `pinned` is `yes` when the install record has `pinned: true` and a string `revision` (`hermes_cli/plugins_cmd_git.py:90-94`), `no` when a record exists otherwise, `unknown` without a record. Hook groups: prompt-altering `pre_llm_call` (context appended to the user message, `agent/turn_context.py:853-857`) and `pre_gateway_dispatch` (rewrites inbound text, `hermes_cli/plugins.py:137-139`); tool/output hooks `pre_tool_call`, `transform_tool_result`, `transform_terminal_output`, `transform_llm_output`; approval observers `pre_approval_request`, `post_approval_response`, `on_human_input_request`, `on_human_input_resolved` (returns ignored, `hermes_cli/plugins.py:144-147`). Hermes follows plugin directory symlinks; the audit never does and reports `symlink_skipped`. Each `hook_plugins` row: `path` (absolute path of the plugin directory; names and versions are not emitted), `version_declared`, `enabled` (true / false / null when the kind could not be verified), `pinned`, `hooks`, `prompt_or_approval_hooks`, `hook_count`, `provides_memory_provider`, `status` (`ok` / `kind_not_verified`). `memory_provider_count` counts exclusive-kind plugins. `missing_or_empty_enabled` rows: `path` (absolute directory path, null for a symlink) and `status` (`empty_dir`, `missing_manifest`, `portable_manifest_not_read`, `symlink_skipped`).

Shell hooks are counted per event from `config.yaml` `hooks:` (`agent/shell_hooks.py:368-447`); command strings are never emitted. Regular files placed directly in `hooks/` are not a Hermes registration format (Hermes gateway hooks are `hooks/<name>/HOOK.yaml` + `handler.py`, `gateway/hooks.py:1-4,41-45`); they are listed with `path` (the file's absolute path when its name matches `[A-Za-z0-9._-]{1,64}`, else null), `size_bytes`, and the `interpreter` class of the first line (at most 256 bytes read).

## 4. Cron (`cron`)

`cron/jobs.json` `{"jobs": [...]}` (`cron/jobs.py:1-3`) and `cron/usage_audit.jsonl` `job_id` (`cron/scheduler.py:2526-2530`) are read (256 KiB each); `cron/output/<job_id>/` names are listed; `cron/executions.db` `executions`/`cron_incidents.job_id` (`cron/executions.py:65-71`, `cron/incidents.py:79-81`) is queried through `_open_user_db`. Runnable = `enabled` and no pause marker (`cron/jobs.py:531-539`). A job runs a script when `script` or `monitor_script` is a non-empty string (`cron/scheduler.py:1516,2272-2279`; `cron/monitor.py:107-114`); `no_agent` alone runs nothing. `failure_streak` counts consecutive failed runs and resets on success (`cron/jobs.py:2413-2417`). Schedule classes: `more_often_than_hourly` (interval < 60 min, or a cron expression firing more than 24 times on an active day), `hourly_to_daily`, `less_often` (including `once` and day/month/weekday-restricted expressions), `unclassified` (shape not recognised). Ghost job ids are counted (`ghost_jobs_count`), not listed; names, prompts, script paths and schedule expressions are never emitted.

## 5. Backup drift and sanity (`config_backup_drift`, `config_sanity`)

`config.yaml.bak`, `config.yaml.bak-*` and `config.yaml.bak.*` in the profile root (credential-named copies skipped) are evaluated for the same enumerated settings only. Order: backups by (mtime, name), current `config.yaml` always last, so the sequence is stable for an unchanged home. Hermes' own current backup location `backups/config/` is not read. Sanity reports KEY NAMES only of enumerated `*.provider` keys holding a URL and enumerated string keys with leading/trailing whitespace (some Hermes readers strip whitespace, e.g. `tools/delegate_tool_config.py:484`).

### Consequence sentences

Each finding carries exactly one of these fixed sentences (`FINDING_CONSEQUENCES`); counts and labels are in the evidence, never in the sentence.

- `unattended_exposure.command_approval_off`: config.yaml sets approvals.mode to off and terminal.backend to local, so Hermes runs shell commands that match its dangerous-command patterns on this machine without asking a person (hardline blocks and approvals.deny rules still apply); this audit read config settings and does not show what commands any agent ran.
- `unattended_exposure.unattended_auto_approve`: config.yaml sets approvals.cron_mode, approvals.unattended_mode or approvals.single_query_mode to approve, so in cron jobs, on unattended platforms (webhook, msgraph_webhook, api_server) or in single-query runs Hermes runs commands and code that match its dangerous-command checks without asking a person (hardline blocks, the runtime self-delete and sudo stdin guards, and approvals.deny rules still apply); this audit read config settings and does not show what commands any agent ran.
- `unattended_exposure.remote_platform_has_powerful_tools`: Config lists, for one or more non-CLI platforms, toolsets that resolve to terminal, code_execution, cronjob or computer_use beyond that platform's shipped default, so sessions arriving on that platform can call those tools while it is connected; this audit read platform_toolsets and did not check whether the platform is connected or whether any remote session called the tools.
- `unattended_exposure.unpinned_prompt_injector`: An enabled user plugin declares pre_llm_call or pre_gateway_dispatch in its manifest and plugins/.install-metadata.json records it as installed without a pinned commit, so a plugin update can change the code that adds context to or rewrites user messages; this audit read the manifest and install metadata, did not load the plugin, and does not show what it added.
- `unattended_exposure.small_model_decides_approvals`: Config keeps approvals.mode at smart and names an auxiliary.approval.model whose name carries a smaller-tier label; in smart mode that model answers APPROVE, DENY or ESCALATE for flagged commands and an APPROVE runs the command without asking a person; this audit read the model name only and did not measure the model's decisions.
- `unattended_exposure.guardrail_disabled`: Config turns off a Hermes safety check that is on by default (protected instruction files, the unattended tool-loop hard stop) or turns on private-network URLs, so that check no longer stops the matching action; this audit read config settings and does not show that such an action happened.
- `unattended_exposure.real_browser_profile`: Config sets browser.use_real_profile to true, so local browser sessions run on a copy of the user's default Chromium-family browser profile, including its cookies and logins, whenever that profile can be copied; this audit read config settings and does not show which sites any browser session opened.
- `unattended_exposure.cron_failing_jobs`: One or more cron jobs in cron/jobs.json have a failure_streak of at least 5, the counter Hermes raises after each consecutive failed run and resets on success; this audit read job metadata and did not read job output.
- `unattended_exposure.cron_runs_scripts`: One or more cron jobs in cron/jobs.json name a script or monitor_script, which the scheduler runs when the job fires; this audit read job definitions and does not show when the scripts ran or what they did.
- `unattended_exposure.ghost_cron_job`: Cron usage, output or execution records, or another job's context_from, name job IDs that cron/jobs.json does not contain; this audit read cron metadata and does not show what those jobs did or why they are absent.
- `unattended_exposure.approval_setting_changed_in_backups`: Approval-related settings in config.yaml differ from at least one config.yaml.bak copy in the profile folder; the copies hold earlier saved values, not when each value was active, and this audit did not check what ran under them.
- `unattended_exposure.config_value_malformed`: One or more enumerated config keys hold a URL in a provider-name field or have leading or trailing whitespace; this audit read config syntax only and did not check how Hermes resolves these values, some of which its readers strip.
- `unattended_exposure.could_not_verify`: One or more unattended exposure settings, plugin manifests, hook entries, or cron records could not be verified from bounded static files; unverified items are not treated as clean or as enabled exposure.

## Thresholds and bounds

- `CRON_FAILURE_STREAK_THRESHOLD = 5`: consecutive failures of one job; a healthy job has none.
- `DELEGATION_*_DEFAULT = 10 / 1 / 250`: shipped defaults.
- `MAX_CONFIG_BYTES = 1 MiB`, `MAX_PLUGIN_MANIFEST_BYTES = 256 KiB`, `MAX_CRON_BYTES = 256 KiB`, `MAX_HOOK_HEADER_BYTES = 256`, `MAX_PLUGIN_INIT_BYTES = 8192`, `MAX_ENTRIES = 2000`, `MAX_DEPTH = 4`, `MAX_TOTAL_BYTES = 8 MiB`, `MAX_SQL_STEPS = 1_000_000`, `MAX_DB_ROWS = 2000`, `MAX_SECONDS = 5.0` (injectable `now_fn`). A hit cap increments `limits['cuts']`, sets `coverage: could_not_verify` and records `truncated_by` (`entry_cap`, `depth_cap`, `file_size_cap`, `total_bytes_cap`, `time_budget`, `row_cap`, `sql_steps`). No wall-clock value appears in the section or the findings, so two runs on an unchanged home give the same raw section; elapsed time is returned beside them as `run_metrics.elapsed_ms`.
- Sizes: the only size is `hooks.files[].size_bytes`, the lstat size of one regular file. Symlinks anywhere in the walked folders (plugins, hooks, cron output, the profile root's backups) are never followed or measured: each is skipped and counted in `limits.cuts` (an enabled plugin directory that is a symlink is listed as `symlink_skipped` with `path` null).

## What it cannot tell

- Not covered: Hermes' own config backups under `backups/config/` (only `config.yaml.bak*` in the profile root are compared) and gateway hook folders `hooks/<name>/HOOK.yaml` + `handler.py` (only regular files directly in `hooks/` are listed).
- `approvals.cron_mode` / `unattended_mode` / `single_query_mode` = approve: the setting is reported (`unattended_auto_approve`), but whether any cron job, unattended platform session or single-query run is active is not.

- Whether any platform is connected, any plugin loaded (`requires_hermes`, catalog kill list), or any command, hook, cron script or browser session ran.
- Environment overrides it cannot read: `TERMINAL_ENV` (when `terminal.backend` is absent), `HERMES_ALLOW_PRIVATE_URLS`, `DELEGATION_MAX_CONCURRENT_CHILDREN`, `--yolo`, hosted-room approval policies.
- Docker backends with host bind mounts take the normal approval flow (`tools/approval.py:1126-1127`); with `approvals.mode: off` they reach host files without prompts. Not flagged (mounts are not inspected). `ssh` runs commands on another host; not flagged.
- Administrator-managed overlays (`/etc/hermes` or `managed_dir`), templates, duplicate YAML keys and unknown scalars report `could_not_verify`.
- Model "tier" is a name convention, not a Hermes concept; capability is not measured.

## Do-not-flag list

- Shipped defaults (`approvals.mode: smart`, messaging bundles that already include terminal, `hard_stop_enabled: false`).
- `approvals.mode: off` with a container or ssh backend, or with `terminal.backend` absent.
- Disabled plugins on disk (`plugins.enabled` is an allow-list), plugins with no install record, pinned plugins, exclusive/model-provider kinds.
- Paused cron jobs with old failure streaks when nothing is runnable (`info`).
- MCP servers being configured (counted only); model/provider selections (only URL-in-provider and whitespace syntax reported, `info`).

## Read policy

- **Listed / lstat only**: `<profile_path>`, `plugins/`, `plugins/<name>/`, `plugins/<category>/<name>/`, `hooks/`, `cron/`, `cron/output/`. Symlinks are never followed (`follow_symlinks=False`, `O_NOFOLLOW`, dir-fd walk).
- **Read (bounded)**: `config.yaml` and `config.yaml.bak*` (<= 1 MiB, enumerated settings only), `plugins/*/plugin.yaml` and `plugins/.install-metadata.json` (<= 256 KiB), first 8192 bytes of `__init__.py` for warning candidates without a declared kind, `cron/jobs.json` and `cron/usage_audit.jsonl` (<= 256 KiB), first line (<= 256 bytes) of regular files in `hooks/`, `cron/executions.db` (`job_id` only, read-only, no sidecars).
- **Never opened**: anything matching `credential_path(path)` or `.env*`, `auth.json*`, `*token*`, `*secret*`, `*credential*`, `*.pem`, `*.key`, `id_*`, `.npmrc`, `.netrc`, `.pgpass`, `.pypirc`, `pip.conf`, or anything under `mcp-tokens/`, `pairing/`, `vault/`, `credentials/`, `secrets/`, `.ssh/`, `.aws/`, `.gnupg/`, `.kube/`, `.docker/`.
